> **Sprint 2 — versão revisada para validação do grupo.** Especificação funcional e roteiro para o protótipo; não é implementação executável. Referências: `04-requisitos.md`, `05-regras-de-negocio.md`, `07-uml.md`.

| Regras aplicáveis | RN01, RN02, RN16 |
| Objetivo | Criar uma conta individual de estudante com e-mail único e perfil principal Estudante. |
| Pré-condições | Visitante não autenticado; serviço de cadastro disponível. |
| Pós-condições | Conta criada uma única vez e associada ao perfil Estudante; em caso de erro, cadastro não concluído. |

## Entradas

- Nome
- E-mail
- Curso
- Senha

## Saídas

- Confirmação de cadastro
- Mensagem de erro e campo a corrigir, quando houver

## Fluxo principal

1. O visitante seleciona **Criar conta** na tela de login.
2. O sistema exibe os campos nome, e-mail, curso e senha.
3. O estudante preenche os campos e solicita o cadastro.
4. O sistema verifica obrigatoriedade e formato dos dados e consulta duplicidade do e-mail (RN02).
5. Com dados válidos e e-mail não utilizado, o sistema cria a conta com perfil Estudante (RN01).
6. O sistema confirma o cadastro e oferece **Ir para login**.

## Fluxos alternativos, exceções e validações

- **A1 — E-mail existente:** o sistema não cria outra conta, informa a duplicidade e oferece acesso ao login/recuperação de senha.
- **A2 — Dados ausentes ou inválidos:** destacar campos com erro e manter os dados não sensíveis para correção.
- **A3 — Falha de serviço:** informar não conclusão e permitir nova tentativa sem duplicar conta.

## Critérios de aceite para inspecionar no protótipo

- Formulário exibe quatro campos e rótulos claros.
- Há estado de erro para e-mail duplicado, sem conta criada na simulação.
- Cadastro concluído leva a uma confirmação e opção de login.

## Navegação / telas previstas para o Stitch

Login → Cadastro → Confirmação → Login
